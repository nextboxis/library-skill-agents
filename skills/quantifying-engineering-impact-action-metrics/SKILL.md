# Quantifying Engineering Impact: The XYZ Action Formula

## When to use
Use this skill when writing resume bullets, performance reviews, promotion packets, or preparing behavioral interview answers.

## Core principles
- **The Google XYZ Formula**: 'Accomplished [X] as measured by [Y], by doing [Z]'. This framework immediately separates high performers from passive participants.
- **Dimensions of Engineering Impact**: Metrics aren't just money. Quantify: Latency (ms), Throughput (QPS), Cost ($/month), Reliability (99.99%), Test Coverage (%), Cycle Time (days to mins).
- **Order of Magnitude Estimates**: If exact numbers are confidential, use defensible orders of magnitude: 'Supported 10M+ daily active users', 'Processed \$50M+ in annualized transaction volume'.
- **Strong Action Verbs**: Replace passive phrases ('Helped with', 'Worked on', 'Responsible for') with definitive verbs ('Architected', 'Optimized', 'Eliminated', 'Engineered', 'Spearheaded').

## Step-by-step workflow
1. Take a baseline task (e.g., 'Worked on backend database performance').
2. Identify the specific engineering intervention [Z] (e.g., 'Added composite indexes and migrated hot tables to read-replicas').
3. Identify the measurable metric [Y] (e.g., 'Query response times and CPU utilization').
4. Quantify the baseline and outcome [X] (e.g., 'Reduced slow query count by 78% and halved database CPU load during peak traffic').
5. Assemble into the XYZ formula and lead with the accomplishment.
6. Audit bullet point to ensure it passes the 'So what?' test.

## Specifics & examples
- **Before and After Transformations**:
  - *Before*: 'Wrote microservices in Python for search functionality.'
  - *After*: 'Engineered distributed search microservice in FastAPI and Elasticsearch, indexing 4M+ documents and cutting query latency from 1.2s to 90ms.'
  - *Before*: 'Helped team fix bugs in payment service.'
  - *After*: 'Resolved critical concurrency deadlock in checkout transaction pipeline, recovering an estimated \$140,000 in monthly abandoned cart revenue.'

## Common mistakes & pitfalls
- Listing job descriptions ('Attended daily standups and maintained Jira tickets') instead of achievements.
- Using fake, overly precise numbers (e.g., 'Improved developer happiness by 37.4%').
- Focusing solely on technologies used without describing what problem they solved.

## Verification checklist
- [ ] Every bullet point includes a tangible, quantified metric or order-of-magnitude scale.
- [ ] Bullet point starts with a strong past-tense engineering action verb.
- [ ] Explains the business or technical outcome clearly to non-domain recruiters.
